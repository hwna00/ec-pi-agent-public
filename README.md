# Pi Agent Harness

**오류 접수부터 조사, 구현, 검증, 업무 기록까지 하나의 흐름으로 연결하는 에이전트 하네스**

Pi Extension API와 MCP 기반의 업무 게시판·브라우저·VS Code·DB 연동, 업무 컨텍스트 참조와 실행 추적.

## 목적

- **업무용 Extension 제작:** 게시글 수집, 테스트 환경 연결, 디버그 콘솔 조회, 시간 로그 작성의 통합
- **하네스 동작 이해:** 도구 등록, 세션 이벤트, 프롬프트 주입, 서브에이전트 위임, 실행 추적의 직접 구성

## 시스템 아키텍처

역할과 도구 배정은 아래 표 기준.

| 연결              | 역할                                           | 연결 방식                                    |
| ----------------- | ---------------------------------------------- | -------------------------------------------- |
| Pi ↔ VS Code      | 디버그 실행, 중지, 서버 콘솔 조회              | `pi-vscode`, 로컬 HTTP 브리지                |
| Pi ↔ Browser      | 게시글 수집, 테스트 환경 접속, 개발자도구 접근 | `context-graph`, Chrome DevTools MCP         |
| Pi ↔ DB           | 스키마, 데이터, 업무 설정 조사                 | 단일 DBHub MCP의 `pg`·`ms`·`my` source         |
| Pi ↔ MongoDB      | 과거 세션 요약 저장, 검색                      | `pi-session-rag`, 벡터, 키워드 검색          |
| Pi ↔ 서브에이전트 | 조사·테스트·리뷰 위임, 메인의 운영 코드 수정    | `pi-subagents`, 다섯 역할 정의               |
| Pi → LangSmith    | 실행 이력 수집, 스레드별 분석                  | 실행 환경의 tracing 연동, LangSmith MCP 조회 |

## 사용 사례

| 단계             | 기존 작업                                         | 개선 후                                                                                   |
| ---------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 접수 내용 파악   | 본문, 답글, 연결 게시글, 첨부파일을 수동으로 복사 | `/load-context`로 자료 저장 → 연결 세션 재개 또는 새 세션 생성 → 경로·트리 참조 전달     |
| 테스트 환경 준비 | 계정 확인, 서버 URL 수정, 수동 로그인             | `/test-server`로 선택 게시글의 연결 정보로 테스트 사이트 접근 및 로그인                   |
| 네트워크 조사    | 대상 탭 지정, URL, payload, response 복사         | 런타임 조사자의 전용 `test_tab`으로 부모 세션의 테스트 탭에 연결, 요청·응답 조회         |
| 서버 로그 확인   | IDE 디버그 콘솔 복사, 전달                        | `vscode_debug_console`로 대상 세션의 출력 조회                                            |
| 실행 과정 점검   | 최종 답변과 터미널 기록 재확인                    | LangSmith로 스레드별 실행, 도구 호출 흐름 분석하여 개선방향 도출                          |
| 업무 기록        | 하루 작업의 수동 정리, 시간 로그 작성             | `/time-log`로 날짜별 세션 요약, 기존 로그 조회와 사용자 확인 후 저장                       |

## 컨텍스트 관리 전략

LangSmith 실행 이력으로 호출 흐름과 반복 탐색 점검.
파일 탐색과 도구 결과의 누적을 줄이기 위한 세 가지 관리 전략.

1. **업무 자료의 참조 전달:** 문서 트리 우선 제공, 필요 시에만 내용을 읽도록 프롬프트 구성
2. **역할별 조사 위임:** 파일 탐색, DB 및 브라우저 접근 등 컨텍스트를 많이 차지하는 작업을 서브 에이전트에게 위임
3. **과거 작업의 검색:** 전체 이력 상시 주입 대신 관련 세션 요약 조회

### 서브에이전트 역할 분리

**메인:** 문제·완료 기준 정의 → 필요한 조사 위임 → 원인 판단과 운영 코드 수정 → 테스트·독립 리뷰 확인.

ContextGraph·세션 관리·Git·시간 기록·RAG는 공통 명령으로 유지.
DBHub·Graphify·IDE·브라우저 조사 도구는 전문 역할에 배정.

| 역할                                          | 담당                                | 주요 도구, 구성                                       |
| --------------------------------------------- | ----------------------------------- | ----------------------------------------------------- |
| 코드 조사자 | 파일·심볼·호출 흐름·원인 후보 | 파일 읽기·검색, Graphify 조회 |
| DB 조사자 | 스키마·데이터·업무 설정 조사, SQL 작성 | DBHub (`pg`, `ms`, `my`) 조회, 업무 설정 스킬 |
| 런타임 조사자 | 서버·브라우저 로그, 네트워크, 디버깅 | `pi-vscode`, 전용 `test_tab`, DebugMCP |
| 테스터 | 승인된 서버 테스트 작성·실행, 회귀 검증 | 테스트 파일 편집·실행, Graphify 조회, 디버그 콘솔 |
| 리뷰어 | 정확성·회귀·과도한 설계·범위 초과 검사 | 파일 읽기·검색, Graphify 조회, 메인이 전달한 diff |

서브에이전트의 추가 조사·판단 요청은 메인으로 전달.
운영 코드 수정은 메인, 사용자 확인 후 테스트 코드 작성은 테스터 담당.
같은 작업 디렉터리의 운영 코드 수정과 테스트 수정은 순차 진행.

**런타임 조사 연결:**

- `runtime-investigator`의 `async: true` 실행과 전용 확장을 통한 부모 세션 테스트 탭 연결
- 자식의 별도 MCP 연결에서 요청 목록부터 조회, 과거 기록이 없으면 기존 캡처 활용 또는 승인 범위의 재현
- 같은 디버그 세션·탭의 실행 제어는 한 런타임 조사자 담당
- 디버그 실행·중지와 외부 상태 변경은 사용자가 요청한 범위에서 수행

조사자·리뷰어에는 쓰기 도구 미배정, 테스터의 수정은 지정한 테스트·보조 파일 범위.
`acceptanceRole` 자체는 도구·파일 경로 권한을 강제하지 않는 역할 표시.
실제 DB·IDE·브라우저 연결 상태는 각 실행에서 별도 확인.

## Custom Extensions

### context-graph: 업무 컨텍스트 수집

로그인한 Chrome의 인증 세션으로 게시판 API를 조회해 본문·상위 작업·연결 게시글·답글·첨부파일을 로컬 저장.

프롬프트에는 선택 글의 메타데이터·저장 경로·문서 트리·Markdown 스키마만 전달.
본문은 `index.md`와 관련 링크를 따라 필요할 때 파일 도구로 조회.

| 명령 | 처리 |
| --- | --- |
| `/load-context <유형>:<번호>` | 관련 자료 수집·저장 후 최신 연결 세션 재개, 연결 세션이 없으면 새 세션 생성·적용 |
| `/load-context --only <유형>:<번호>` | 상위 작업으로 확장 없이 시작 글·명시적 참조 글 재귀 수집 |
| `/apply-context [유형:번호]` | 재수집 없이 저장된 맥락을 현재 세션에 적용 |

연결 작업은 수집 후 로컬 배정.
연결 세션 선택은 현재 분기의 게시글과 배정한 작업이 일치하는 세션만 대상.

**테스트 탭 연결:**

- 선택 문서의 `test_accounts`를 읽어 테스트 서버에 접근·로그인, 누락 정보는 입력으로 보완.
- Pi 세션과 Chrome `targetId` 연결 후 `test_tab`에서 MCP 스키마 확인, `pageId` 자동 지정.
- 동일 URL의 다른 탭으로 자동 대체 금지.

### pi-vscode: IDE 디버깅 연동

VS Code 보조 Extension의 디버거 출력 수집과 인증된 로컬 HTTP 브리지 기반의 Pi 연동.

- **실행 제어:** `launch.json`의 실행 정보를 읽어 디버깅 실행·중단
- **콘솔 조회:** `vscode_debug_console`의 세션, 커서별 기록 조회
- **출력 수집:** VS Code와 디버거 사이의 통신 규약인 DAP의 출력 이벤트 활용

### pi-session-rag: 세션 기억 관리

- **저장:** `/rag-summary`로 세션의 작업 내용 요약 → Cloudflare BGE-M3 임베딩 → MongoDB 업로드
- **검색:** `/rag-search`로 현재 프로젝트의 자료 검색
- **순위 결합:** 의미 유사도 기반 벡터 검색과 오류명, 식별자 중심 BM25 검색 병행. RRF로 두 검색의 순위 결합

### time-log: 일일 업무 기록

날짜별 Pi 대화와 당시의 작업 연결 정보로 업무 로그 초안 생성.
기존 로그 조회·사용자 확인 후 저장, 수동 입력한 시간과 기존 행 보존.

### DBHub: PG·MSSQL·MySQL 읽기 전용 조사

하나의 `dbhub` MCP에 PostgreSQL(`pg`)·MSSQL(`ms`)·MySQL(`my`) source를 연결하는 구성.

| 용도 | 역할에 배정한 도구 |
| --- | --- |
| 스키마 조사 | `search_objects_pg`, `search_objects_ms`, `search_objects_my` |
| SQL 조회 | `execute_sql_pg`, `execute_sql_ms`, `execute_sql_my` |

DB 조사자는 조회용 SQL만 작성·실행.
읽기 전용 설정과 DB 계정 권한은 별도 관리, 실제 접속 가능 여부는 환경별 확인.

### 공통 관리 명령

| 확장·명령 | 기능 |
| --- | --- |
| session-label-editor | 게시글·작업 선택과 세션 라벨 표시 |
| gco | Git 소스·산출물 브랜치 동기화 |
| switch-db-connection | `/switch-db-connection <0~99>`로 DBHub의 PG·MSSQL·MySQL 서버 번호 일괄 변경 |

DB 연결 변경은 Pi가 대기 중일 때 실행.
DB 주소는 전체 검증 후 한 번에 저장하고 설정 재로드, 미설정 연결은 제외.
